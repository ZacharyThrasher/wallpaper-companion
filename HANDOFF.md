## Decisions and files

- `src/mcp/server.ts` exports `createCatalogMcpServer(readOnlyCatalog)`. Its dependency type excludes catalog commits. Six tools expose status, wallpaper/playlist list/get, and preview path metadata. Strict Zod input objects reject unknown keys; page size is capped at 100, with bounded strings/integers and revision-aware pagination. All tools advertise read-only/idempotent/non-destructive/closed-world hints. Successful structured content preserves the domain envelope with projected data, accompanied by a concise summary and usable JSON text fallback identical to the projected object. Domain/index failures include the same fallback and an actionable structured error; SDK validation failures retain the SDK text error format.
- `src/mcp/projections.ts` uses explicit field allowlists. Wallpaper lists return ID/title/type/tags/availability/optional Workshop ID/hasPreview. Playlist lists return ID/name/memberCount/unresolvedCount. Details add registered paths/provenance/time, or playlist profile and ordered position/file/wallpaperId/resolution members. MCP v1 exposes no raw opt-in: project/cache metadata, playlist/member raw copies, settings, presets and timing payloads remain only in the catalog/CLI. No catalog preservation semantics change.
- `src/mcp/index.ts` constructs the catalog with a read-only repository adapter. Each query opens `SqliteCatalogRepository(filename, true)` and closes it in `finally`. Missing files return an empty status without creating files/directories. No scan or filesystem media read is performed, and the repository's replace operation always fails. This permits separate CLI scans to become visible on subsequent calls.
- `src/mcp-cli.ts` starts official SDK `serveStdio` with explicit legacy-client support. stdout is protocol-only; help and fixed diagnostic messages go to stderr. stdin EOF and termination signals close the connection. It accepts only `--db` and `--help`; tool calls cannot select another database.
- `src/adapters/database-path.ts` extracts the unchanged default-index helper for both entry points. `src/cli.ts` imports and re-exports it to preserve its API; no scan behavior changes. Catalog, scanner, SQLite, and Steam adapter internals were not edited. No upstream fixes were needed for this feature.
- `package.json` / lockfile pin coherent exact dependencies: official server/client 2.3.1, core 2.3.1 transitively, Zod 4.6.7, TypeScript 5.9.3, and Node types 24.19.2. Client SDK is dev-only. Added `mcp` and `test:mcp` scripts. Registry package availability and published exports were verified before implementation.
- `test/mcp.test.ts` adds eight synthetic protocol/integration groups. `docs/local-mcp.md` documents contract, projections, fallback, operational limits, and absolute built-command examples for Codex, Claude Code, Claude Desktop, and Gemini CLI, with official sources. README links the local MCP interface.

## Limitations and next actions

- **External client setups are documented, not tested.** SDK protocol compatibility does not prove how Codex/Claude Code/Claude Desktop/Gemini CLI present results to their models. Text-only hosts now receive the same compact JSON as structured content, in addition to summaries. The coordinator/user chooses the actual client validation sequence.
- `node:sqlite` is experimental; its warning remains visible on stderr. The existing backend deserializes a complete snapshot per operation. Projections omit raw payloads but page bounds limit item counts, not the bytes of long titles/tags, normalized member lists or diagnostics. Queries reflect the last scan, and consecutive calls can see different revisions. Clients must restart pagination after `REVISION_CHANGED`.
- Preview lookup returns registered path metadata only. Image serving would require fresh disk-containment/content checks and is outside this feature. HTTP/remote authentication, MCP Apps, scanning tools, wallpaper controls and installation are excluded.
- The earlier private-repository Actions budget failure is historical: the user made the repository public for standard CI, and the coordinator triggered fresh runs. No billing changes or CI bypasses were made. The first public run exposed a runtime-specific warning assumption in the test; the test now compares to the executing Node build.
