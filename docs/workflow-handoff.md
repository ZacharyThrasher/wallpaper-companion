## Delivered contracts

- `src/workflow/preferences.ts`: separate companion-owned SQLite v1 store (application ID `0x57435046`), strict bounded fields, exclusive initial file reservation, ownership checked under `BEGIN IMMEDIATE`, expected per-reference revisions and atomic rollback. Keys are saved playlist IDs or `global`; guidance/query/tags/exclusions/dismissed/shortlist shared across gallery and optional stdio. No credential field or source-config writes. A simultaneous first startup can safely refuse an uninitialized file; retry after the other process is ready. It never assumes a foreign empty file is safe to initialize.
- `src/workflow/service.ts`: deterministic bounded title/tag evidence over unique resolved reference members, explicit prose kept separate, editable controls, no semantic/image claims. Steam provider search excludes installed/dismissed IDs, duplicate candidates and explicit exclusions. No-key returns only a real Steam search URL. Inspection validates exact public item URLs/positive uint64 IDs before anonymous metadata. Shortlists page metadata in 50-item batches with displayed/total/nextOffset and preserve up to 1,000 IDs. No subscription, download, native playlist editing, or paid model API.
- `src/workflow/runtime.ts`: shared runtime with env-only Steam credentials, existing catalog read-only adapter and validated PlaybackService. Refresh invokes existing guarded CLI scan at a server-owned destination. Gallery startup must explicitly choose defaults (`--refresh-defaults`) or matching trusted scan path/profile options; no configuration means actionable refusal, preserving custom indexes. Browser requests cannot select roots/profile/path. Refresh busy admission and gallery playback busy admission are bounded.
- Gallery routes in `src/gallery/server.ts` add same-origin session/CSRF token, strict bounded POST JSON actions and workflow reads. Existing ID-only contained raster preview validation remains intact. CSP adds only exact provider-approved HTTPS Steam CDN image hosts; no image proxy/server arbitrary fetch. Actions call WorkflowService, PlaybackService or guarded refresh. Acceptance, verified target observation, engine errors and possible application after timeout stay distinct. Monitor 0 is explicit in the UI.
- `src/mcp/companion.ts` exports `registerCompanionReadTools`, `registerCompanionActionTools`, and `createCompanionMcpServer`. Read tools include deterministic context, paged shortlist metadata, anonymous inspection and actual registered preview images (PNG/JPEG/GIF/WebP, 2 MiB, gallery validation). Optional actions expose preference writes/discovery and explicit validated playback. Structured data has a compact JSON text fallback. The original `createCatalogMcpServer(catalog)` remains six read-only tools; optional server instructions can be supplied for the companion factory. HTTP remains unchanged/read-only. `mcp-cli --companion` is opt-in; default stdio remains unchanged.
- `ui/src/Discover.tsx`, `Playback.tsx`, App/API/styles integrate reference selection, editable guidance/hints/exclusions, honest Steam handoff, inspect/shortlist/dismiss, conflict reload, large-shortlist navigation, Apply wallpaper, Play playlist, Read current state and Refresh library. Reload view remains separate. Saving disables fields to preserve edits; result cursors stay tied to the submitted search. Quiet incumbent design is preserved.
- README now explains actual user flows; technical CLI depth moved to `docs/catalog.md`. `docs/discovery.md` documents API/store/tool limits and setup. ## Limits and coordinator decisions

- No live apply/play/scan was issued in implementation. All captures and mutation tests use synthetic data/mocks. Existing live catalog was not read or copied. Anonymous Steam transport is mocked here; previous provider live verification is recorded in its own docs. No Steam key was available, so credentialed live search remains unverified. Named external AI client image presentation also remains unverified.
- Saved prose is not automatically converted into search controls. An AI host interprets richer intent using explicit preferences, evidence and optional actual images; match explanations remain simple title/tag overlap. Backend evidence loads catalog pages once per request, but the underlying snapshot repository still parses a full snapshot per page and discovery is limited to 10,000 wallpapers.
- Exact URL acceptance intentionally excludes short links, extra parameters and fragments. Shortlist results may include unavailable/private/deleted items. Opening Steam never proves installed/subscribed state. Shortlists remain separate from native saved playlists.
- Refresh requires deliberate startup source/profile configuration, rather than guessing how a pre-existing index was created. Playback uses the existing installation/OS-profile validation; stale or nonmatching saved playlists can fail safely. UI targets monitor 0; bounded optional tool inputs allow another monitor.
- The design sidecar was already stale before this feature; it was reported and preserved. A separate `document` refresh can reconcile it if desired. No client configuration, startup task or user setting was edited.
